# 丞丞ABC · 产品分析报告

> 分析时间：2026-10-08
> 分析对象：丞丞英语乐园（https://www.zelab.cn/）——面向 5 岁孩子（宋程程）的线下培训班作业补充 PWA
> 分析视角：**这个产品真的让孩子学进去了吗？下一步该强化什么、放弃什么？**
> 事实来源：代码（src/）、数据（lessons.ts / heroes.ts）、设计文档（DESIGN-GUIDELINES.md）、线上部署状态

---

## 执行摘要

**判断**：产品的"学习内核"已经成立（6 种活动闭环 + 错词复习 + 点读发音 + 即时反馈），但**"外壳工程"已经超过了"内容生产效率"**——下一步应停止加游戏化功能，把精力转向**降低增量加课成本**和**验证孩子真实学习效果**。

**最关键的 3 条事实**：

1. **课程是增量的、跟着老师节奏走**：目前 5 课（l4-l8），老师教一首新歌，爸爸加一课。这意味着瓶颈不是"总量不够"，而是"**每加一课爸爸要花一整天**"——图片找图/时间轴对齐/对话编写，这些手工环节拖慢了加课速度。
2. **功能量远超内容生产效率**：6 种活动 + 双模式 + 游戏路线图 + 开宝箱三连击 + 41 个奥特曼图鉴 + 贝壳货币 + 连击 streak + 家长报告 + 错词复习 + 暗黑模式 + 三端适配——**这些外壳的工程投入，远大于每课内容生产本身**。
3. **学习闭环有科学内核**：听音选图答错进复习池、间隔重复、点读发音、即时反馈不惩罚——这些是经过验证的儿童语言学习机制，方向正确。

**核心取舍**：

| 方向 | 决策 |
|---|---|
| **保留并强化** | 6 种活动核心闭环、错词复习（间隔重复）、一切可点即发声、即时反馈不惩罚、家长报告 |
| **停止新增** | 不要再加游戏化外壳（宝箱/图鉴/连击/路线图已经够了）、不要做更多活动类型 |
| **P0（下一步最该做的）** | **把加一课的成本从 1 天压到 1-2 小时**——写加课脚本、批量出图、模板化对话，让老师教完新歌当天孩子就能用上 |
| **Non-goals** | 不做社交、不做 AI 对话、不做付费、不做更多视觉动画 |

**最大不确定性**：**孩子真的在学吗？**——目前没有任何"孩子实际使用数据"（使用时长、正确率、错词复习完成率）回流到开发者视角。家长报告页面存在，但**爸爸自己看过几次？**这是比任何新功能都重要的问题。

## 1. 产品现状盘点

### 1.1 内容侧（孩子真正学的东西）

| 项 | 现状 | 评价 |
|---|---|---|
| 课程数 | 5 课（l4-l8：A Sailor / Music Man / Rainbow / Count / ABC Song） | **严重不足**。5 岁孩子词汇量目标是几百词，45 词只够一周 |
| 每课单词 | 7-11 个，全部来自童谣歌词 | 合理——童谣情境记词比孤立记词有效 |
| 童谣 | 5 首经典英文儿歌（音频/歌词高亮/时间轴同步） | 选曲正确，都是高频启蒙曲目 |
| 单词图片 | 自定义 PNG（175×140），存在 public/lessons/ | 有真实图片资源，不是 emoji 兜底 |

### 1.2 功能侧（爸爸花时间做的东西）

| 模块 | 完成度 | 对 5 岁孩子的价值 |
|---|---|---|
| **6 种学习活动**（看图学词/听音选图/连线/跟读/唱童谣/亲子对话） | ✅ 完整 | **核心价值**。这是产品存在的理由 |
| **错词复习**（间隔重复队列） | ✅ 完整 | **科学价值最高**。错题自动进复习池，到期出现 |
| **一切可点即发声**（Web Speech TTS） | ✅ 全站 | **核心价值**。孩子不认字，点读是唯一交互 |
| **即时反馈**（答对彩带/答错不惩罚） | ✅ 完整 | 符合儿童学习心理 |
| **自由练习模式**（/learn 课程列表） | ✅ 完整 | 主入口，家长好理解 |
| **游戏闯关模式**（/game 多邻国式路线图） | ✅ 完整 | **价值存疑**——5 岁孩子看不懂"地图导航"，且和自由模式重复 |
| **开宝箱**（三连击开箱 + 抛物线收奖励） | ✅ 完整 | 有仪式感，但**边际效用递减**——开 5 次新鲜，开 50 次就麻木了 |
| **贝壳货币** | ✅ 完整 | 孩子能理解"收集"，但用途单一（只是数字） |
| **奥特曼图鉴**（41 位英雄详情页） | ✅ 完整 | **爸爸的情怀 > 孩子的需求**。41 个英雄，孩子真正认识几个？ |
| **连击 streak**（连续学习天数） | ✅ 完整 | 对成人有效（多邻国），对 5 岁孩子**没有意义**——孩子不会为了"连续 7 天"主动学习 |
| **家长报告**（时长/单词/错词） | ✅ 完整 | 有价值，但**爸爸真的看过吗？** |
| **暗黑模式** | ✅ 完整 | 5 岁孩子晚上用手机？——使用场景存疑 |
| **PWA 离线可用** | ✅ 完整 | 合理——家长可能不想每次加载 |

### 1.3 技术侧

- Vue 3 + Vite + Pinia + vue-router（hash）+ TypeScript + Vitest（217 测试）
- 纯前端，无后端，localStorage 存进度——**数据只在孩子那台设备上，换手机/清缓存就没了**
- 部署在 GitHub Pages 自定义域名 zelab.cn
- 设计文档完善（DESIGN-GUIDELINES 8 条原则 + tokens.css 唯一事实源 + TDD 流程）

## 2. 产品分野：这个产品和"多邻国"到底哪里不同？

| 维度 | 多邻国（Duolingo） | 丞丞ABC | 产品含义 |
|---|---|---|---|
| **用户** | 成人自主学习 | 5 岁孩子 + 家长陪同 | 孩子是"玩家"，爸爸是"产品经理"——不要把成人的游戏化习惯强加给孩子 |
| **驱动力** | 连击、排行榜、愧疚感（未学习提醒） | 贝壳、宝箱、奥特曼、星星 | 5 岁孩子的驱动力是"**当下好玩 + 家长表扬**"，不是"长期收集" |
| **内容量** | 几十门语言、几千课、持续运营 | 5 课、45 词、无运营 | **内容是硬瓶颈**——外壳再精致，5 课学完就没了 |
| **使用场景** | 用户自己打开，每次 5-10 分钟 | 家长（妈妈）陪孩子，线下培训班作业补充 | 这不是"孩子自主产品"，是"**家长辅导工具**" |
| **反馈机制** | 答错直接告诉正确答案、连续错劝退 | 答错不提示正确答案、只标红让孩子重试 | **丞丞ABC 这个设计更对**——5 岁孩子需要"再试一次"的缓冲，不要直接挫败 |
| **商业模型** | 订阅 + 广告 | 无（家庭自用） | 不需要考虑留存/转化——**只需要考虑"孩子真的学了吗"** |

**三个关键分野**：

1. **"孩子自主产品" vs "家长辅导工具"**——丞丞ABC 是后者。所以所有设计都应该问：**妈妈陪孩子用时，这个交互是帮她省时间，还是给她添乱？**
2. **"长期收集动机" vs "即时快乐动机"**——5 岁孩子为"这一次答对了有彩带"兴奋，不会为"我已经攒了 50 个贝壳"兴奋。连击/图鉴/宝箱这些"长期动机"模块，对这个年龄段是**过度设计**。
3. **"内容驱动" vs "外壳驱动"**——多邻国的核心是内容量（你永远学不完），丞丞ABC 当前的核心是外壳（宝箱/路线图/图鉴）。**方向反了**。

## 3. 产品决策：下一步做什么？

### 3.1 必须做（P0）

**把"加一课"的成本从 1 天压到 1-2 小时。**

课程是跟着培训班老师的节奏**增量加**的——老师这周教哪首歌，爸爸下周加一课。这意味着瓶颈不是"总量不够"，而是"**每加一课都要花爸爸一整天**"。加课成本高 → 爸爸加课意愿低 → 孩子学完一课等很久才有新课 → 产品价值下降。

**加一课现在要做什么、哪里最耗时：**

| 步骤 | 当前做法 | 耗时占比 | 优化方向 |
|---|---|---|---|
| 1. 选曲 + 歌词整理 | 老师给童谣，爸爸整理歌词文本 | 10% | 已经很快 |
| 2. 选词（8-12 个核心词） | 从歌词里挑高频词 | 10% | 已经很快 |
| 3. **单词图片 8-12 张 PNG** | 找图/手绘/AI 生成，统一风格，裁成 175×140 | **50%** | **最大瓶颈**。写脚本：输入单词列表，批量 AI 出图，统一扁平卡通风格，自动裁剪 |
| 4. 歌词时间轴（song-timings.json） | 手工对着音频标每句起止时间 | 20% | 可以简化为"整段歌词滚动高亮"而不是逐句时间轴；或用音频识别自动对齐 |
| 5. 亲子对话句（TalkView） | 老师提供对话内容，爸爸直接录入 | 5% | 老师给什么就录什么，不需要模板化或自己编 |

**具体动作**：
- 写一个 `scripts/add-lesson/` 工具：输入童谣标题 + 歌词 + 单词列表，自动生成 lessons.ts 课程对象骨架、批量出图、生成 song-timings 占位
- 图片统一用 AI 生成（风格一致：扁平卡通、白底、儿童友好），不要手工找图
- 亲子对话是老师提供的，加课时直接录入老师给的句子即可，不需要爸爸自己编或模板化

**目标**：老师教完一首新歌，爸爸当天晚上花 1-2 小时就能把课加好，孩子第二天就能用。

### 3.2 应该停止做（Stop）

| 模块 | 为什么停 |
|---|---|
| **再开新游戏化功能** | 宝箱、图鉴、连击、路线图、贝壳——已经够了。再加就是"爸爸自娱自乐" |
| **双模式（自由 + 游戏）并行维护** | 同一个课程两个入口，孩子到底走哪个？建议**合并**：自由练习为主入口，游戏路线图只作为"完成课程后的奖励地图"，不再做独立闯关逻辑 |
| **41 个奥特曼图鉴** | 砍到孩子真认识的 10-15 个。其余的是爸爸的收藏品，不是孩子的学习激励 |
| **暗黑模式** | 5 岁孩子晚上不玩手机。这个开关收到"我的"页就够了，不要再优化 |
| **新活动类型** | 6 种活动（看图/听音/连线/跟读/唱童谣/亲子对话）已经覆盖了儿童词汇学习的主要方式。再加就是功能堆砌 |

### 3.3 应该加强（Enhance）

| 方向 | 具体动作 |
|---|---|
| **家长报告真正用起来** | 爸爸每周看一次孩子的报告：哪些词错得多？哪些课没做完？这是唯一的"学习效果反馈"回路 |
| **错词复习的体验** | 这是产品里最有学习价值的模块，但目前是被动触发（到期才出现）。建议在"我的"页加一个"今日复习"入口，让妈妈知道今天该复习哪几个词 |
| **亲子对话的实用性** | TalkView 目前是点句听发音，但**真正的亲子对话是妈妈和孩子说**。建议每课的对话句配中文翻译，妈妈知道这句话什么意思，才能和孩子真的说起来 |
| **数据备份** | 现在进度只存在 localStorage——换手机、清缓存就全没了。建议至少加一个"导出进度 JSON"按钮，妈妈可以存到微信文件传输助手 |

### 3.4 明确不做（Non-goals）

- ❌ 不做社交/好友/排行榜（孩子不需要，家长也不需要）
- ❌ 不做 AI 对话/智能问答（TTS 已经够了，AI 对话对 5 岁孩子是噪音）
- ❌ 不做付费/订阅/内购（家庭自用）
- ❌ 不做英语以外的语言（这是给丞丞学英语的）
- ❌ 不做 iPad/手机以外的端（Mac 能用就够了，不需要做 App Store 原生应用）
- ❌ 不追求"像多邻国一样"——多邻国是成人产品，丞丞ABC 是 5 岁孩子的产品，不要硬对标

## 4. 验证计划：怎么知道方向对了？

不要加新功能来"证明产品好"，而是用现有数据验证学习效果：

| 验证项 | 怎么测 | 通过标准 |
|---|---|---|
| **孩子真的在学吗？** | 连续观察 1 周：妈妈陪孩子用时，是主动打开还是需要催促？ | 主动打开次数 > 催促次数 |
| **错词复习有效吗？** | 看家长报告：错词在复习后是否还会再错？ | 同一个词错 3 次以上 → 说明教学方法有问题（图片/发音/选词） |
| **加课速度跟得上老师节奏吗？** | 老师教完一首新歌，爸爸多久能把课加好？ | > 3 天 → 加课流程要优化；当天加好 → OK |
| **游戏化壳有用吗？** | 观察：孩子是为了"开宝箱"继续学，还是为了"妈妈表扬我"继续学？ | 如果是后者 → 宝箱/图鉴可以再简化 |
| **家长报告有用吗？** | 问妈妈：你上周看过家长报告吗？知道丞丞哪几个词不熟吗？ | 如果答不上来 → 报告要做得更简单/更醒目 |

## 6. 一句话总结

> **丞丞ABC 现在像一个装修得非常精致的小教室——但每加一张新课桌都要爸爸手工搭一整天。**
>
> 装修（游戏化外壳）已经超过了实际需要。下一步不是再装更好看的灯，而是**让加课这件事变快**（脚本出图 + 模板化对话），并且**每周去看一次孩子的成绩单**（家长报告真正用起来）。
>
> 对 5 岁孩子来说，**"这一课真有趣"比"我又攒了 50 个贝壳"重要 100 倍**。
