# ADR-006: 磨耳朵播放页「浮层让位」而非「藏掉底栏」

## Status

Accepted（2026-10-17 落地；推翻了此前「播放页隐藏底部导航」的做法）

## Context

磨耳朵（`#/listen`）的播放页是一个盖在列表上的浮层。它自带完整 transport（上一首 /
主播放键 / 下一首 / 进度条），与底部导航（学习 / 磨耳朵 / 我的）天然构成「一屏两个底部」。

上一版的解法是**藏掉底栏**：`shouldShowNav(path, player.nowPlaying)` 在 `/listen` 且播放页
展开时返回 `false`。这个做法有两个代价：

1. **播放页成了全站唯一没有导航的页面**：退出只能靠左上角收起键，播着歌想切去学习，
   必须先收起播放页；
2. **更容易踩到那次事故的雷**：判断里掺了 `nowPlaying` 这个脱离路由的全局状态。
   更早的事故是 `三首页 && !nowPlaying`——从播放页用系统返回手势离开 `/listen` 时
   `nowPlaying` 不复位，于是 `/course` 上整条底栏一起消失，屏幕上没有任何 tab，
   孩子彻底回不去磨耳朵。

另外，播放模式（循环 / 随机）的状态在 `player` store 里一直存在（`repeatMode` /
`shuffleOn` / `toggleRepeat` / `toggleShuffle`），但**界面上没有任何入口**——
状态可写不可达，等于没有这个功能。

## Decision

1. **浮层让位，底栏常显**：播放浮层不再 `inset: 0` 盖满全屏，下边界改为
   `bottom: calc(var(--nav-h) + env(safe-area-inset-bottom))`，只占底栏之上的空间。
   底栏规则退化为「只认路径」：`shouldShowNav(path)`，第二个参数删除。
2. **层级兜底**：底栏 `--z-floating(40)` > 浮层 `--z-bar(30)`。即使以后边界算法被改坏，
   也是底栏压在浮层上，不会重演「导航整条消失」。
3. **补上播放模式入口**：播放页 transport 上方加一行「随机 + 循环三档」
   （顺序播放 → 列表循环 → 单曲循环），按钮带中文标注。
4. **两种模式互斥**：随机开着时不能停在「单曲循环」（自动退回列表循环）；
   切到「单曲循环」时自动关掉随机。见下方 Consequences。

## Consequences

**变好的：**

- 播放页也能直接切 tab，播放由全局 store 续着不中断；退出不再只有一条路。
- 底栏显隐只依赖路由路径，删掉了「全局状态参与导航判断」这一类事故的入口。
- 播放模式从「store 里有、界面上没有」变成可达；中文标注让三种循环状态不再靠猜。

**变差 / 需要接受的：**

- 播放页可用高度少了约 `--nav-h`(100px)：靠 `.pl-lyrics` 的 `margin-block: auto`
  吸收富余高度，歌词窗仍是固定 5 行的「窗口」而非拉满整页；小屏（iPhone SE 一类）
  是最紧的一档，后续若再往播放页加元素，要先做窄屏实测。
- 「一屏两个底部」的视觉拥挤是**被管理**了、不是被消灭了：浮层的 transport 与底栏
  之间只有 `var(--gap-m)` 的呼吸。这是拿「少 100px 高度」换「随时可导航」的取舍。
- 互斥规则意味着「随机 + 单曲循环」这个组合不可达。这是刻意的：它同时亮着时
  `next()` 里 `one` 的分支会先返回，按钮写着「随机」、实际永远播同一首。

**可以回退的方向：** 若后续窄屏实测确实撑不下，优先把顶栏的「播放列表」收进抽屉、
或把歌词窗缩到 3 行，**不要**回到「藏底栏」的方案（那正是本 ADR 要解掉的问题）。
